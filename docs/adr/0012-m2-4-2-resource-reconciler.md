## Architecture
Trusted internal ResourceReconciler, constructed with existing WorkspaceManager, SandboxController and optional QA runner; no agent HTTP endpoint, paths, shell/Docker flags or generated grants. Owner-human initiates reconciliation for one Run only. ResourceInventory reads DB under Run-first lock, bounded Docker observations and configured private workspace root. Inventory includes workspace, producer/seed/reader/input/output, QA holder/seed/job/input, durable Import/Patch/QA/Verification summaries and permanent Artifact references. IdentityVerifier compares DB Run/Workspace/repository/lease issuance, current operator grant, profile, exact Docker labels/image/config/mounts, root/provenance and observed immutable IDs. Unknown ownership is QUARANTINE, never adoption. Controller label discovery is read-only; names/prefixes never authorize deletion.

StateComparator protects any unrevoked unexpired lease regardless of terminal presentation; only expired/revoked/cancelled runs can be candidates. Active work is KEEP. Missing/invalid lease and inconsistent bindings QUARANTINE. Persistent evidence roots and objects always KEEP. Workspace cleanup is only the exact UUID worktree under configured root, verified Git registration and fixed Base. No arbitrary directory tree deletion or orphan private-root deletion. Unknown root entries are QUARANTINE; recovery capsules are retained, not GC.

CleanupPlanner persists a strict versioned CleanupJournal in existing IdempotencyRecord (namespaced key), with actor/Run/repository/lease generation and version, canonical observed fingerprints, per-resource disposition and ordered actions. Dry-run records plan/audit only. No SQL migration: head remains 0007; add cleanup-journal.v1 JSON schema. CAS on journal version plus Run-first lock serializes reconcilers. Execution requires explicit plan ID and expected version; atomically commit EXECUTING intent BEFORE effects. Then reauthorize, lock Run before journal, recheck lease generation/version and whole inventory, and inspect each target immediately before exact removal. Containers removed by immutable ID; volumes by exact name plus creation/options/labels fingerprint and zero foreign attachments. Docker has no atomic volume-generation delete API: trusted daemon/operator exclusivity is required; never force remove an attached volume.

Hold Run lock during bounded cleanup effects to serialize with heartbeat/publication/other reconciler execution; existing resource methods already honor Run-first locking. Do not call existing multi-resource destroy by name. Remove only this plan's containers, then unattached volumes, then registered worktree; update Sandbox/Workspace lifecycle and QA cleanup tombstones transactionally. Never alter Import/Patch/QA verdict/Verification results, budgets, artifacts or approvals; no workload replay. Generation and resource/journal version must match. Cleanup is not an execution capability.

DB/daemon failure fails closed; no successful deletion claim on uncertainty. Committed EXECUTING after a lost result is UNKNOWN on retry, never automatically repeated. An explicitly NEW dry-run can inventory remaining exact resources; this is cleanup planning, not workload recovery. Persist stable error audits without credentials/raw daemon errors. Audit DB outage remains unavailable. Partial effects are reported UNKNOWN and require a new reviewed plan. No background service, Crash Recovery, Retention/GC, real Codex or SCM/deploy operations.

## Trusted controller usage

Construct `DockerResourceBackend(existing_output_or_sandbox_controller, existing_qa_runner)` and `ResourceReconciler(existing_workspace_manager, backend=backend)` in operator-owned code. Invoke `plan(authenticated_owner_human, run_id, stable_request_key)`, inspect the returned typed CleanupJournal, then `execute(same_actor, run_id, plan.plan_id, plan.version)`. Agent workers are denied this administrative API. There is no public endpoint or automatic scheduler. A workspace-only reconciler can omit the Docker backend only when no Sandbox/QA allocations exist.

Plan and execution never accept host paths, shell strings, Docker options or generated ownership claims. Run-first SQL write lock precedes all journal/resource access. Journal version CAS uses an SQL request_hash predicate binding Run/key/version on both databases; generation/lease-version SQL CAS protects effects. Docker health is mandatory even when resources appear absent. Re-inspection occurs at whole-plan and per-target boundaries. Container deletions address full immutable IDs, not names. Volume names are bound to expected UUID role/labels/options/CreatedAt and must have no remaining attachments before removal. Foreign attachments quarantine the entire plan before any deletion. Docker exposes no atomic generation-based volume delete; a trusted exclusively controlled daemon and private roots are assumptions.

Docker mount/environment ordering is semantically normalized for fingerprints; duplicate environment names are denied and command/entrypoint order remains significant. No raw Docker environment, private seal key or lease token appears in journals/audits. Worktree content hashing uses bounded no-follow descriptors with pre/post file identity checks, rejects links/special files/credential paths and binds the private root inode/device and Git registration/Base. Only the registered exact worktree is removed. `.manager`, source repositories, unknown private-root entries, immutable artifacts and every recovery capsule/candidate remain outside deletion scope. No recursive private-root GC is implemented.

Active unrevoked future leases KEEP resources even when the Run is already presented for human review. Expired/revoked resources may be reclaimed only after exact ownership checks. The reconciler does not revoke a live lease or cancel work on behalf of a generated report. It never changes approvals, verdicts, budgets or Artifact verification. Sandbox/Workspace cleanup states and QA cleanup tombstones are updated only after confirmed absence; missing allocations may reconcile to cleaned state without issuing deletes.

PLANNED -> EXECUTING intent commits before effects -> COMPLETE / QUARANTINED / UNKNOWN. A changed observation or generation is quarantined before effects. Mid-cleanup failure is UNKNOWN with confirmed attempted completion keys; a DB final-commit failure may leave EXECUTING even after physical deletion. A retry of an uncertain execution records UNKNOWN, never repeats its effects. Explicitly request a NEW plan after investigation to inspect remaining resources; no workload or automatic Crash Recovery is provided. Completed retries return historical results to the same owner, not a new authority. Idempotency keys must be unique per Run/plan; reusing across Runs is denied.

No SQL migration is necessary: typed versioned `contracts/cleanup-journal.v1.schema.json` uses existing IdempotencyRecord and WorkflowEvent; Alembic head remains 0007. Original migrations/models/modules/tests remain intact. Remote CI, malicious daemon/admin/same-UID attacker, filesystem snapshot atomicity, physical power loss and multihost operation are unverified. Container inspection/deletion cannot constitute a host sandbox. Permanent retention policy, orphan private capsule GC, unknown ownership adoption and background resource/workload recovery are deferred.
