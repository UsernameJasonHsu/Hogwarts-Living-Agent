## Architecture / ADR 0014
Add internal operations package: strict versioned contracts, StorageUsageAccounting, AggregateResourceQuotaManager, ReferenceProtector/Hold service, VersionedRetentionPolicy, SafeGarbageCollectionPlanner, guarded execution, OperationalPrototypeController and operational health. Reuse existing IdempotencyRecord and WorkflowEvent, with owner/actor/namespace binding and version request_hash CAS; no new SQL DDL, head 0007. No public Agent administration endpoint.

Quota limits, profiles, root registration and retention policies are supplied by trusted operator wiring, immutable to Agent. Reserve only a named profile: fixed slots/CPU/memory/PIDs/storage peak, bound to owner/Run/project/issued generation. Run lock first, owner aggregate ledger lock second, CAS all mutations. Aggregate all held reservations across Runs; never automatically release on time/lease expiry, uncertainty or process disappearance. Initialize the ledger explicitly as owner-human. Resource absence and current ownership are required for human release. M1 money is never changed by quota accounting.

OperationalPrototypeController reserves then persists an execution intent before calling existing deterministic verification; result receipt is cached without new historical byte reads. IN_USE/UNKNOWN cannot invoke workload again. Existing low-level M1/M2 interfaces remain compatible and trusted-internal; mandatory production-wide admission wiring is an M3 readiness gate, not silently claimed. Legacy unreserved sandboxes deny new admission. Reservations are conservative capacity commitments, not measured CPU use or actual monetary spend.

Storage accounting scans only operator-registered owner-exclusive private roots outside source repositories; bounded no-follow metadata traversal, reject links/reparse/hardlinks/special files, check tree stability and free space/inodes. Report logical bytes, Artifact declared bytes and reservation bytes separately; do not claim deduplication, Docker-volume physical-byte metering or filesystem hard quota. Admission combines observed private-root usage, pending peak reservations and minimum disk headroom; unknown DB/daemon/filesystem state denies. Full physical disk filling is tested by deterministic ENOSPC injection, not by endangering the host. Kernel/filesystem hard quota and native Linux production capacity remain unverified readiness gates.

Retention v1 applies ONLY to identified ephemeral container/volume/worktree resources already eligible under M2.4.2. All Artifact objects, Review Bundles, source repos, journals, recovery capsules/candidates and unknown objects are permanent KEEP/QUARANTINE. DB reference snapshot binds Run evidence, proposal, approvals/merge intent, artifacts/import/journal identities; active review, durable human Hold, unknown execution, live lease, unexpired retention or quarantined inventory blocks GC. Manual Hold changes require owner-human, expected version, Run-first CAS and audit. No Agent changes policy/limits/Holds.

GC defaults to dry-run. A separate explicit human approve binds exact plan/version/policy/reference/resource snapshot and finite approval TTL. Execution persists intent, revalidates generation, policy, holds/references and identity, then delegates to the existing exact Reconciler. Add a default-no-op trusted execution guard to CleanupPlanner/Executor, called inside its existing Run lock before each deletion. This serializes Hold changes with GC and closes the gap between an outer reference check and deletion; normal M2.4.2 behavior remains unchanged. No broad prune, object unlink API, autonomous scheduler or unknown workload retry. Partial/uncertain effects become UNKNOWN and are not replayed; request a NEW reviewed plan after investigation.

Health is owner-human only, bounded and sanitized: capacity/held commitments, logical storage/free space, active/unknown/quarantined counts, stable error codes and readiness blockers. Unknown dependencies yield unhealthy/blocked, never false zero or ready. No raw Docker env, private path, token, seal key or secret in reports. Metrics are local snapshots, not an external monitoring deployment.

## Final internal wiring and limits
OperationalPrototypeController is the M2.4.4 admission entrypoint. Existing low-level trusted APIs remain compatible; production-wide mandatory enforcement is not claimed. Every loaded quota commitment is validated against its registered profile/demand and owner/Run/project/worker/issued-generation binding. Ledger history remains held through restart/unknown execution and is capped at 1000 entries; limits/profile changes require a reviewed operator migration, not Agent edits or automatic resets.

Reference inspection is owner-human only. Existing ArtifactStore pure metadata and no-follow SHA/size helpers validate READY artifacts under the already-held Run lock, with no nested transaction, lifecycle mutation or trust promotion. Foreign owner/producer/lease bindings are blocked before any byte reads. Missing verifier, PENDING/non-ready object, corruption, unresolved reference or IO uncertainty blocks GC. Capsules/journals and all artifacts remain permanent even when unreferenced. The Reconciler guard is trusted wiring and defaults to no-op for existing callers; GC installs it per execution instance to avoid cross-thread mutable context.

Storage reports logical bytes, declared Artifact bytes and unmaterialized commitment bytes separately. Admission charges existing logical bytes plus unmaterialized Artifact bytes plus held profile storage commitments; free-space headroom is also required. This conservative double-accounting of still-held peak commitments is intentional until explicit absence-based release. Snapshots are bounded and sanitized; physical Docker-volume byte metering and kernel hard quota remain unverified. M3 readiness stays blocked by external CI/incident/production wiring and capacity/restore gates regardless of local test success.
