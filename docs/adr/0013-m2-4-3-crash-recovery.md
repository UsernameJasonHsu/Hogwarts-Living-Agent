Add internal CrashRecoveryCoordinator, WorkflowStateInspector, RecoveryClassifier, RecoveryPlanner, RecoveryExecutor, Versioned RecoveryJournal and HumanInterventionQueue. Invalid/missing resources, daemon/DB outage, corrupt or ambiguous evidence fail closed.

Classification:
- SAFE_RESUME: only an existing authenticated complete Import capsule, BUILT/PUBLISHING Patch candidate/proof, complete known QA execution capsule or Verification ReviewBundle capsule. Only original authenticated worker with original still-live lease/current grants can publish. Human never impersonates worker. Explicit publication-only adapters forbid intent creation, PENDING execution/capture and any workload start; normal original APIs remain compatible. Unknown QA/verification execution without complete proof is MANUAL_REQUIRED and never replayed. Pure trusted Git proof reconstruction is data validation, not workload execution.
- FINALIZE: known legal terminal pairs and intact evidence; no-op historical confirmation, or terminal metadata cancellation normalization using existing human-cancel proof, or conservative budget settlement. READY Run plus ACCEPTED/REJECTED/DEFERRED Proposal is legal and must not be downgraded; no approval renewal or auto decision/merge. Stale pending human approval requires manual intervention.
- MANUAL_REQUIRED: busy/unsealed/unknown execution, changed generation/lease/grant, incomplete identity, tampering, stale approval, unsupported state/cost or inconsistent counters. Keep immutable evidence and unknown facts. Queue reports stable reason and observation hash; owner-human acknowledgment only records triage and grants no execution/approval authority.

## Durability / fencing / cleanup separation

## Operation and recovery semantics

Trusted wiring: `CrashRecoveryCoordinator(existing_orchestrator, backend=DockerResourceBackend(existing_controller, existing_qa), stale_seconds=60)`. `recover(principal, run_id, key, original_lease_token=None)` defaults to dry-run. `execute(principal, run_id, recovery_id, expected_version, original_lease_token=None)` explicitly applies the inspected action. `scan(owner_human, limit=50)` is bounded (1..100), owner-scoped, ignores recovery audit activity and skips fresh active work and already-consistent terminal no-ops. It is an explicit call, not a background scheduler or automatic workload retry.

Inspect / plan require current ownership, repository grant and safe source configuration. Worker inspection of Artifact bytes requires a live claimed Run, exactly as in the existing ArtifactStore. Only owner-human may inspect historical bytes after expiry/revocation/completion; original cleanup credentials do not grant new byte-read rights. SAFE_RESUME additionally requires the live unrevoked issued generation, unchanged grant/context and exact proof. An owner-human can inspect and finalize proven bookkeeping, but cannot impersonate the worker. No lease renewal, takeover, approval renewal or automatic human decision is added.

Publication-only entrypoints were added to Importer, Patch Builder, QA Runner and Verification Orchestrator. They reject absent/PENDING intents, missing complete proof and transitions into execution/capture. Existing ordinary APIs retain their defaults. Recovery invokes these entrypoints only; it never calls controller start/execute, QA execution, source programs or cleanup. Trusted Git candidate verification may read/rebuild indexes in a private data workspace; this is not executing repository code.

RecoveryJournal.COMPLETE means the selected recovery ACTION completed. It does not mean every workflow is ready or QA passed. The immutable plan observation and separate result observation expose the post-action classification and component hashes. For example publishing a known QA result after a crash can complete while the enclosing Verification has no authenticated bundle and remains MANUAL_REQUIRED. That follow-up is placed in human triage rather than rerunning the pipeline. Missing/unsealed QA remains unknown even if an unauthenticated test-process marker reports exit zero.

SQL generation/lease-version predicates and journal-version hash CAS are used under Run-first locking before intent and finalization. Multiple plan keys cannot start competing SAFE_RESUME actions while another recovery is EXECUTING/UNKNOWN. Uncertain recovery intents are not replayed. A NEW plan may finalize independently proven committed downstream facts; unresolved publication work otherwise requires manual investigation. An acknowledgment in the HumanInterventionQueue changes only triage status, never execution rights or proof requirements.

Budget release uses existing M1 release only for verified deterministic zero-billable-adapter provenance with a terminal audit/bundle and consistent aggregate reservation counters. It records a versioned zero-cost proof digest bound to Run/reservation/amount/evidence; this is not a new real-provider billing ledger. Owner budget is locked before Agent, after Run. Other Runs' reservations remain held. Missing/foreign reservation, counter drift, unknown cost or unsealed execution is manual. Existing RELEASED records are not settled again. Known historical M1 fake success/failure and legitimate ACCEPTED/REJECTED/DEFERRED/FAILED/BLOCKED/CANCELLED pairs are preserved; no statuses are invented from Agent prose.

Inspection reads immutable bytes and metadata without calling mutating Artifact read/repair paths; corruption is reported for intervention, never fixed or promoted. Both recovery schemas use existing IdempotencyRecord/WorkflowEvent tables, so Alembic remains 0007. No Retention/GC or permanent-object deletion exists.

## Verification boundaries

Portable tests use explicitly fake workload/resource adapters with real local Git, immutable stores and SQLite/PostgreSQL. Linux integration kills a real trusted Python Worker/Controller child with SIGKILL at durable checkpoints and rebuilds service objects against the same DB/storage; it does not simulate process death with an exception. Cases include sealed ReviewBundle, pre-final-commit death, partial Artifact publication, unsealed real QA and generation revocation. The child receives only test configuration and fixed image IDs; its private DB/lease file is mode 0600 and never packaged. Runtime workloads never receive the controller socket or test DB credentials.

Docker Desktop Linux VM validation is not native Linux-host/production deployment validation. Actual host power loss, storage/DB-server hardware failure, malicious privileged daemon/admin or same-UID root manipulation, cross-host recovery and multiprocess coordinator stress remain unverified. Docker-unavailable and DB failure injection are separated from real process SIGKILL. Remote CI and real Codex remain unverified. Existing long transactions can delay locks; UTC service clocks and trusted DB/private roots remain prerequisites. Unsupported or revoked grants can deny inspection rather than expose private files. Default manual triage is a safe outcome, not a claim of automatic recovery of every crash window.


## Artifact read-authority refinement

An intermediate regression was interrupted after review identified that cleanup authorization must not be reused for worker Artifact byte inspection. Inspector now requires the original active Store-compatible worker authorization before any fresh byte reads. Owner-human historical inspection keeps its existing authorization. After Verification commits a terminal Run, Recovery records only the typed trusted publisher result corroborated by committed Run/journal/budget fields; it does not read Artifact bytes again on behalf of the completed worker. That receipt is distinguished by the trusted_publisher_commit component. Existing cached receipts remain historical operation facts, not new read or execution capabilities. Dedicated expiry/revocation/completion and post-terminal-read spies test this boundary. All interrupted outputs are retained and final suites must be rerun on the refined source.
